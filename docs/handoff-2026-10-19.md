## How we build: what's going wrong

**Tokens.** From 2026-10-14 to 10-19 this session and its 134 agents used about 19 billion tokens:
18.3 billion of it re-reading context, 0.6 billion writing it, and 37 million output. An agent averaged
450 to 650 thousand tokens of context a call over 400 to 1,400 calls. Hunter's read: the subagents
re-read code and logs constantly.
- **Each agent learns the codebase from nothing.** There are 52.5 thousand lines of GDScript, 355
  probes, 13 PRDs (808 KB, the biggest 1,100 to 1,500 lines) and a 3,657-line lore file. Every fresh
  agent reads its PRDs and the code it touches. With six in parallel, each learned the same chassis,
  Console, deeds and power code over again.
- **Logs and probe output come back into the context:** every probe run, every CI failure, every
  look-test and every merge of master.
- **What it read stays:** on a long run, everything an agent read and thought is carried and re-read
  on each later call.

**Limits.** All four Opus agents running hit the weekly limit within minutes of each other and
stopped mid-work.

**CI.**
- Verify branches run Linux only. macOS and Windows run only on master, so a platform failure shows
  after landing. Three such landed this round:
  - devices 30's radio reading a station's report, fixed;
  - two timing probes run on macOS's slower runners, now left to Linux.
- One landing at a time: a second finds master moved and needs another run.

**Parallel agents collide:**
- the same files: `assets/audio/CREDITS.md` three times, deed counts in the profile PRD,
  `Deeds.TABLE`, the creative menu's `GROUPS`;
- the same probe numbers: saves 24, 35; weather 23.

**Shared machine:**
- The GPU lock queues unseen captures: one waited ten minutes behind another.
- The local suite lock jammed with seven agents, so whole suites go to CI.
- Hunter's game shares the GPU.

**Look-tests are fragile:**
- after merging master, a worktree needs a re-import or the look-test hangs on script errors and
  holds the GPU lock;
- the Walker's sheet comes out grey.

**Ideas, not decided:**
- A short code map (module → files → the classes and functions that matter), so an agent finds what
  it needs without reading around.
- PRDs split into the agreed design and the as-built detail. The as-built prose, with its measured
  numbers, is most of what agents read.
- `scripts/probe.sh` and `verify.sh` saying only failures and a one-line summary by default.
- A follow-up in a system goes to the agent that built it (resumed with SendMessage), which already
  knows the code.
- Fewer agents at once on code that overlaps.
