# Survey receiver visual contract

The receiver is the first replaceable device appearance. Its default remains the
original procedural model, including its shared worn material and lineage shell.
The design decision lives in [Radio](prd/radio-sound-and-atmosphere.md#replaceable-receiver-appearance-agreed-2026-10-22).

## Ownership

`SurveyReceiver` owns signal acquisition, frequency, strength, power, sounds,
deeds and saved state. Catalog owns its size, mass, collision and physical battery
socket. A `ReceiverVisual` scene owns geometry, control pivots, the reading anchor
and material adaptation. Visual scenes contain no physics bodies, gameplay
scripts or replacement battery sockets. Keep the receiver's physical envelope
(0.36 × 0.50 × 0.26 metres) and the existing battery socket clear.

The visual root uses the receiver's local coordinates, metres, +Y up and +Z
facing out of the instrument. Its origin is the catalog box centre. Keep that root
at the identity transform; put import-axis corrections below it.

## Author a replacement

1. Export the Blender model as glTF/GLB, with moving pieces separate and their
   pivots at their real hinges/axles. Apply intended scale before export.
2. Create a Godot wrapper scene whose root uses `ReceiverVisual` (or a visual-only
   subclass). Instance the imported model below that root. Keep the wrapper outside
   the imported scene so reimport does not overwrite its configuration.
3. Assign the exported references in the inspector:

   | Reference | Purpose |
   | --- | --- |
   | `shell` | Main case MeshInstance3D; remains the device's frame view |
   | `meter` | Needle pivot; local +Z is its rotation axis, rest points to mid-scale |
   | `tuning` | Tuning pivot; receives the existing continuous dial rotation |
   | `volume` | Volume pivot; receives the existing volume rotation |
   | `reading` | Marker for reading view; +Z faces out of the screen |
   | `painted_meshes` | Meshes receiving wear/light state; empty collects all descendant meshes |

   Pivots may be ordinary Node3D parents of one or more meshes. Their authored
   rest positions, orientations and scales are preserved. Names and hierarchy can
   differ from the procedural model. Keep all assigned nodes below the visual root.
4. Use `visual_scene` on a receiver before it enters the tree, or call
   `replace_visual(scene)` on a live receiver. For a new project-wide default,
   replace the contents of `game/look/receiver/survey_receiver_visual.tscn` with the
   wrapper. Receiver gameplay and saves require no changes.

A live replacement rejects embedded collision bodies/shapes and validates the required references before retiring the working
appearance and immediately reapplies the current control and appearance state.
Invalid configured appearances fall back to the original scene at startup.
Appearance choice is an asset configuration, not a new item/save identity.

## Materials and lineage

The default uses the exact existing meshes and Paint shader. Its moving pieces
and shell still receive `age`, `era` and `lit` instance shader parameters. Catalog
lineage changes enter through `Device.apply_frame_look`; the procedural visual
accepts the generated shell, while imported visuals retain their authored shell.

The Paint shader relies on custom mesh vertex channels generated by `Paint.Pieces`.
A plain Blender export does **not** supply these channels. An imported visual must
provide a compatible material or override `appearance(age, era, lit)` to adapt
those values. `age` is the existing computed paint age, `era` the existing mark
atlas row, and `lit` is one only while the receiver is switched on and powered.
Use per-instance uniforms or private material instances to avoid changing every
copy of the receiver. Model-specific maker marks belong in this visual adapter;
they are not automatically projected onto arbitrary imported geometry.

Inventory previews copy the authored hierarchy's mesh transforms, material and
surface overrides, plus the three instance parameters. Meter previews use the
same authored pivot with the current measured strength. Other custom per-instance
shader parameters or skeletal animation would need an extension to the preview
contract; neither is required by this rigid instrument pilot.

## Acceptance

Exercise controls, stowing and legacy saves with the existing radio checks.
Radio 77 replaces a live, fitted receiver with an independently authored hierarchy,
checks state and physical fittings remain intact, applies lineage, draws its
inventory preview, then restores the original worn appearance. The fixture is a
simple authored Godot scene, not a Blender art replacement.

For an off-screen renderer check of either wrapper, run:

```sh
scripts/unseen.sh --path . --resolution 960x720 res://look/receiver_visual/receiver_visual.tscn -- /tmp/receiver-captures [res://path/to/wrapper.tscn]
```

This saves fresh, worn and rear views outside the repository. It exercises the
real material shader, unlike headless checks.
